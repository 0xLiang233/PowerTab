# Power Tab v1 产品草案

## 一句话定位

Power Tab 是一个替代浏览器新标签页的高效入口：

- 帮你优先复用已有 tab，减少重复打开
- 提供常用网站的快捷入口
- 保留 Tab Out 式的 tab 分组与清理能力

它不是书签管理器，也不是复杂工作台。

---

## 核心目标

1. 打开东西更快
2. 尽量复用已经打开的 tab
3. 让 tab 清理变得低成本
4. 保持产品边界简单，便于后续工程维护与扩展

---

## v1 范围

### 1. 智能搜索框

支持：

- 默认搜索引擎为 Google
- 可切换搜索引擎
- 输入内容时优先匹配已打开的 tab
- 如果没有命中已打开的 tab，则行为尽量接近浏览器地址栏
- 支持 URL、域名、站点词、普通关键词输入

确定的 v1 规则：

- 走效率型交互：默认优先执行第一候选
- 第一优先级永远是已打开的 tab
- 已打开 tab 的匹配顺序：精确 URL > 高相关 URL/域名 > 标题/站点词匹配
- 若没有匹配到已打开 tab：
  - 像浏览器地址栏一样处理输入
  - 看起来像 URL / 域名就直接打开
  - 否则走当前搜索引擎搜索
- 候选列表可显示 open tabs、quick apps、search action，但默认动作应优先落在最相关的已打开 tab 上

### 2. 快捷入口区

定位：

- 页面上的常用网站快速入口
- 更像 app launcher，不是书签管理器
- v1 采用扁平 icon 列表，不做分组

支持：

- 添加快捷入口
- 删除快捷入口
- 编辑图标 / 名称 / URL
- 排序
- 点击入口时直接打开新 tab，不复用已有 tab

视觉与交互：

- 以 icon 为主
- 不需要复杂卡片化
- 更接近浏览器首页 app launcher 的感觉
- v1 图标策略：优先读取目标网址的 favicon；如果没有可用 favicon，则回退到默认占位图标；后续版本再支持自定义图标

推荐入口示例：

- Gmail
- GitHub
- Claude
- Notion
- Vercel
- YouTube

### 3. Tab 管理区

继承 Tab Out 的核心价值：

- 按域名分组展示打开中的 tab
- 首页类 tab 单独归组
- 重复 tab 检测
- 单个关闭
- 整组关闭
- 关闭重复项
- 点击跳转到已有 tab

---

## 明确非目标

v1 暂时不做：

- 完整书签系统
- 多级收藏夹
- 稍后读/归档系统
- 多端实时 tab 同步
- 复杂工作区 / workspace 管理
- AI 自动分类

---

## 页面结构建议

首页整体重心：**Tab 管理优先**。

也就是用户打开新标签页后，首先看到并感知到的是当前打开 tab 的整理和清理能力；搜索框与 Quick Apps 是高频辅助入口，但不抢主视觉。

```text
┌─────────────────────────────────────────────┐
│ Power Tab                                   │
│ [ 搜索 / 输入网址 ] [Google ▼]              │
│ [Quick Apps icons...]                       │
├─────────────────────────────────────────────┤
│ Open Tabs                                   │
│ - Homepages                                 │
│ - github.com                                │
│ - claude.ai                                 │
│ - localhost                                 │
│ - youtube.com                               │
└─────────────────────────────────────────────┘
```

---

## 用户心智

Power Tab 的核心心智应该是：

> 搜索框先复用，快捷入口直接打开，Tab 区负责整理。

也就是：

- 搜索框优先判断是不是已有 tab
- 快捷入口是固定入口，点击直接新开
- Tab 区负责清理和整理

---

## 数据持久化建议（v1）

本地存储即可：

- quick apps 列表
- 搜索引擎偏好
- 可能的首页布局偏好
- 用户的 tab 分组配置（如果后面支持）

不需要持久化：

- 当前打开中的 tab 状态
- 当前窗口布局

---

## 后续服务化方向

如果将来要做后端，同步的重点应放在：

- quick apps
- 用户偏好设置
- 自定义规则

而不是一开始就同步运行态 tab 数据。

---

## 搜索候选列表展示

- 候选列表采用简单的视觉分组：
  - Open Tabs
  - Quick Apps
  - Search
- 分组只是 UI 上的轻量划分，不影响全局候选排序逻辑
- 默认选中项仍然是全局最相关的第一候选
